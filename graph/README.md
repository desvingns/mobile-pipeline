# graph/ — демонстрация Mobile Pipeline

Главный вход — `index.html`. Четыре уровня объяснения одной истории:

| Режим | Что показывает |
|---|---|
| **Простыми словами** | Восемь этапов добавления избранного в рецепты: роли, действия, результат и интерактивный макет телефона. |
| **Как это устроено** | Условия запуска, последовательность, параллельные исследователи и ссылки на технические ноды. |
| **Все детали** | Исходный редактор графа в `expert.html`, со всеми агентами, потоками и источниками. |
| **Презентация** | Видеорассказ 3:53, русская озвучка, встроенные титры, главы и полный текст. |

Сценарий следует реальному brownfield-маршруту: три экземпляра `grounding-scout`
исследуют проект параллельно; реализация, тестировщик и запуск тестов идут
последовательно. Автоматический показ — учебная анимация, реальные агенты не запускаются.

## Управление историей

- Кнопки этапов, «Назад» / «Далее» или стрелки клавиатуры переключают сцену.
- «Показать работу» демонстрирует порядок. «Остановить показ» возвращает исходное состояние.
- Карточка участника раскрывает вход, действие, результат и условия запуска. `Esc` закрывает описание.
- Переключение уровня сохраняет выбранный этап. Макет телефона реагирует на нажатие сердечка.
- `prefers-reduced-motion` отключает движение и ускоряет демонстрацию до итоговых состояний.

## Данные демонстрации и видео

`story/scenario.js` — роли, экземпляры участников, тексты, озвучка и ссылки `ref`
на техническую карту. Здесь отдельно хранятся три задания одного исследователя.
`story/timing.js` генерируется из измеренной длительности голоса, вручную не правится.
Технические `data/*.js` сохраняют свой прежний формат и проверки покрытия.

Видеопроект находится в `../videos/mobile-pipeline/`; его README описывает
пересборку и проверку. Папка `media/` содержит готовый MP4, постер и SRT.
Все ресурсы сайта локальные; Node и HyperFrames нужны только для разработки и рендера.

Ссылки: `#simple/research`, `#guided/checks`, `#presentation/repair`,
`#details/checks/mp-dev/feature/mp-tester-android`. Старые ссылки на конкретные
ноды продолжают работать. `#overview/all` теперь открывает простой обзор;
полная карта обзора доступна через `#details/idea/overview/all`.

## Техническая карта

Node-view в духе n8n / ComfyUI / UE Blueprints: ноды с портами входа и выхода, подписанные
связи, боковая панель с объяснением каждой ноды **на русском, простыми словами**, на одном
сквозном примере — «Избранное» в приложении рецептов.

Три графа:

| Граф | Что показывает |
|---|---|
| **Обзор** | как `/mp-spec` и `/mp` стыкуются: пять сквозных пайплайнов из `README.md` |
| **/mp-spec** | сборка спеки: фазы A.0 → F, три режима интейка, два человеческих гейта |
| **/mp** | конвейер разработки: роутер, 15 режимов, агенты, скрипты, гейты, слой контрактов |

## Как открыть

**Локально** — открой `graph/index.html` двойным кликом. Никакого сервера не нужно:
данные лежат в `data/*.js` и подключаются обычным `<script src>`, а не через `fetch()`
(через `file://` он запрещён).

**По ссылке** — граф публикуется на GitHub Pages workflow'ом `.github/workflows/pages.yml`
при каждом изменении `graph/**` в `main`.

### Управление полной картой

| Действие | Как |
|---|---|
| панорама | тащить фон мышкой |
| масштаб | колесо мыши, кнопки `−` / `+` |

| ссылка на конкретную ноду | адрес вида `#mp-dev/feature/mp-developer-android` |

## Как править граф

Топология **написана руками** — она не генерируется из `templates/`. Это осознанный выбор:
генератор не сможет написать человеческое объяснение с примером, а без объяснений граф
бесполезен. Расплата — граф может устареть, и от этого его страхует `tests/test-graph.sh`.

### Формат данных

Каждый файл в `data/` — обычный JSON внутри однострочной обёртки:

```js
window.MP_GRAPH_REGISTER({
  "id": "mp-dev",
  ...
});
```

Комментарии внутри допустимы **только целой строкой** (`/* ... */` от начала и до конца
строки) — валидатор вырезает именно такие, а всё остальное разбирает как строгий JSON.

### Нода

```jsonc
{
  "id": "mp-developer-android",
  "kind": "agent",              // agent | script | gate | artifact | mode | contract | board | note
  "title": "Разработчик",       // русское имя на карточке
  "tech": "{{PREFIX}}-developer-android",
  "model": "claude-opus-4-8",
  "tools": ["Read", "Write", "Edit", "Bash"],
  "flags": ["пишет код", "коммитит"],
  "src":  "templates/android/agents/{{PREFIX}}-developer-android.md",
  "also": ["ещё/один/файл.md"],  // необязательно: дополнительные исходники
  "ports": {
    "in":  [{ "id": "spec",  "label": "SPEC" }],
    "out": [{ "id": "files", "label": "changed_files + коммит" }]
  },
  "ru": {
    "what":    "Что делает — обязательное поле.",
    "example": "На «Избранном»: ...",
    "in":      "Что получает на вход.",
    "out":     "Что отдаёт.",
    "why":     "Зачем это отдельная нода.",
    "stops":   "Когда останавливает конвейер."
  }
}
```

**Правило заголовка.** `title` отвечает на вопрос «зачем этот шаг» — коротко, по-русски,
глаголом: «Написать код», «Сверить с оригиналом», «Проверить руками перед пушем». Имя команды,
её флаги и id агента живут в моноширинном `tech` под заголовком — в заголовок они не попадают
никогда. Максимум 40 символов; `tests/test-graph.sh` заваливает сборку, если в заголовке
оказалась команда, плейсхолдер `{{…}}` или он длиннее лимита.

Правила остального текста: русский, простыми словами, без жаргона там, где без него можно
обойтись. Поле `example` — всегда про «Избранное», чтобы примеры складывались в одну историю.

### Ребро

```jsonc
{
  "id": "dev-to-review",
  "from": "mp-developer-android:files",
  "to":   "script-reviewer:files",
  "label": "changed_files",
  "kind": "data",              // data | gate | retry | fallback | blocked
  "only": ["feature"],         // необязательно: ребро только в этих потоках
  "not":  ["tdd"]              // необязательно: во всех потоках, кроме этих
}
```

`from` берёт **выходной** порт, `to` — **входной**. Порт можно не указывать — тогда берётся
первый подходящий, а если портов нет вовсе — середина стороны карточки.

### Поток (flow)

Поток — это просто список id нод. Рёбра подхватываются автоматически: попадают все, у
которых оба конца есть в потоке и разрешает `only`/`not`. Одна и та же нода живёт в разных
потоках без дублирования русского текста.

### Раскладка

Считается автоматически: колонка = длина самого длинного пути от начала, порядок внутри
колонки = порядок объявления в потоке. Петли (рёбра `retry`) находятся обходом в глубину и в
расчёт колонок не идут, поэтому цикл не уносит ноды вправо до бесконечности.

Подкрутить можно двумя способами: `"row": 2` — позиция внутри колонки, `"pos": {"x":…, "y":…}` —
жёсткие координаты.

## Что проверяет `tests/test-graph.sh`

1. Файлы вьюера на месте, и в них нет `fetch()` / ES-модулей (иначе сломается `file://`).
2. Каждый `data/*.js` — валидный JSON в правильной обёртке.
3. Каждый `src` и `also` существует на диске (ловит переименования).
4. **Каждый агент и скрипт из `templates/` упомянут хотя бы одной нодой** — или явно внесён
   в `data/ignore.txt` с причиной. Добавил агента и забыл граф — CI красный.
5. Каждый режим из `manifest.tsv` имеет свой поток в `mp-dev.js`.
6. Все концы рёбер и все id в потоках существуют; у каждой ноды есть `ru.what`, а её `title` —
   короткое «зачем этот шаг» без команды и плейсхолдеров.
7. `pipelineVersion` совпадает с корневым `VERSION`.

Запуск: `bash tests/test-graph.sh`. В CI он идёт в `validate-plugins.yml`.

Проверка поведения нового интерфейса (Node 24):

```bash
npm ci --prefix tests/graph-demo --ignore-scripts
npm test --prefix tests/graph-demo
```

Она проверяет связь сценария с исходными нодами, ожидание всех параллельных
результатов, последовательную работу, отмену показа, четыре режима, старые ссылки,
описания участников и главы видео. Тесты выполняются отдельной задачей CI.

Результаты проверки готовой поставки и ограничения: [VALIDATION.md](VALIDATION.md).
